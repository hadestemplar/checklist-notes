# checklist-notes · 把任意文字材料整理成一堂规范的清单体笔记

一个 Skill：给它一段口述稿、一份会议记录、一篇长文、一份抓课包底稿，它按**清单体笔记**的规范产出可长期复用的 Markdown 笔记。

```
素材（口述 / 会议记录 / 长文 / 课程底稿） ──▶ 清单体笔记（分层、分点、可扫读、可回看）
```

---

## 一、它解决什么问题

绝大多数笔记的问题不是「记少了」，是**记完再也不看**：

- 大段散文，回看时找不到落点
- 层级混在一起，三层以下和正文分不清
- 只有结论没有关键词，扫读成本高
- 有时反过来：为了形式好看把内容砍到只剩骨架，半年后连自己都读不懂

这个 Skill 把验收标准定成一句话：**半年后能不能只靠这份笔记复述要点。** 形式不合格可以改，内容不足直接判不合格。

## 二、它是什么

| 文件 | 作用 |
|---|---|
| `SKILL.md` | 工作流：判档 → 收素材 → 还原结构 → 定骨架 → 填要点 → 自检 → 出稿；外加格式硬规范、模板区合并规则、ASR 术语对照 |
| `references/清单体笔记-判据库-v1.2.md` | 判据库：按档位（L2–L6）的规则、自检项、错误对照、溯源 |
| `templates/课程笔记模板.md` | 课程类笔记的外壳（frontmatter + 七节）；非课程素材可不用 |

两份文件分工明确：`SKILL.md` 管**怎么做**，判据库管**做到什么程度算合格**。

## 三、安装

```bash
cp -r checklist-notes  ~/.dsh/skills/yitang-checklist-notes
```

（目录名与 frontmatter 的 `name` 保持一致即可。）

## 五、规范摘要（完整版在判据库）

**编号**

- 主层 `1. `，子层缩进一个 Tab 后 `a. `
- 绝不写 `1、` `a、` `1)` `- ` `*`——顿号在 Markdown 里不是列表语法，渲染出来是一行死文本；字母顿号反而会被编辑器接管重编号
- 条与条之间空一行；二级及以下不再额外换行

**每一点**

- 以 `**关键词：**` 开头，再写内容；单点 ≤ 50 字
- 层级 ≤ 3；散文段 ≤ 3 行

**两章职责二分**

- 第 1 章（归纳章）：问题定义 / 为什么学 / 学完得到什么 / 本质。由整理者提炼，不是搬运
- 第 2 章（搬运章）：素材本体的内容，与原始结构（课程大纲 / 会议议程）一一对应
- 两章不许串：第 2 章不再重复第 1 章讲过的背景

**两类骨架**

- 叙事型章节（案例、故事）：按 SCQA 走——背景 → 冲突 → 问题 → 解法，一个案例一条完整故事线
- 方法型章节（方法、步骤、工具）：按五问走——现象是什么 → 为什么要做 → 典型原因 → 解法 → 注意事项

**三条硬自检**

- 数量对账：素材承诺「4 个阶段」，正文就必须有 4 个；缺的进「待确认」，不许拿后一阶段的成果顶替
- 收尾段不丢：素材结束时的收口、下一步、作业/交付要求，必须出现在最后一节
- 无重复：把两章主旨句并排看，删掉后一条不损失信息 → 判重复，合并

## 六、已知限制

- 编号形式（顿号 vs 标准有序列表）在不同渲染器里表现不同。本库统一用标准有序列表；粘进某些富文本编辑器（如飞书文档）会被重编号，这是宿主行为，不是笔记错误。
- 判据库的档位（L2–L6）来自特定方法论，用于判定「写到什么程度」；不需要档位时按格式硬规范执行即可。
